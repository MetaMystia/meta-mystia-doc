# Getting started

This guide is for contributors who are familiar with C# and .NET but may not have experience with Unity IL2CPP mod development. It explains the repository's build configuration and the basic reverse-engineering tools.

## Building the project

Before you start, make sure your system meets the following requirements and complete the setup in order.

1. **.NET 10 SDK**:
   [https://dotnet.microsoft.com/download/dotnet/10.0](https://dotnet.microsoft.com/download/dotnet/10.0)

2. A **legal copy** of [Touhou Mystia's Izakaya](https://store.steampowered.com/app/1584090) (Steam version).

3. Clone the **MetaMystia** repository:
   [https://github.com/MetaMystia/MetaMystia](https://github.com/MetaMystia/MetaMystia)

4. Download the latest **BepInEx-Unity.IL2CPP-win-x64**:
   [https://builds.bepinex.dev/projects/bepinex_be](https://builds.bepinex.dev/projects/bepinex_be)

    and extract it completely into the game's install root (the folder containing `Touhou Mystia Izakaya.exe`).

5. Launch the game once and quit after reaching the main menu. BepInEx generates the `core`, `interop`, and other assemblies needed to build the project.

6. In the MetaMystia repository root, copy the local configuration template:

    ```powershell
    Copy-Item MetaMystia.local.props.example MetaMystia.local.props
    ```

7. Edit `MetaMystia.local.props` and set `BepInExPath` to the `BepInEx` folder in the game directory:

    ```xml
    <Project>
      <PropertyGroup>
        <BepInExPath>game install folder\BepInEx</BepInExPath>
      </PropertyGroup>
    </Project>
    ```

    `MetaMystia.local.props` matches the repository's `*.local.props` ignore rule and should not be committed. The project references the assemblies in `BepInEx/core` and `BepInEx/interop` through this path, and outputs build artifacts to `BepInEx/plugins`.

8. Open `MetaMystia.sln` in an IDE that supports .NET solutions, or run this in the repository root:

    ```powershell
    dotnet build MetaMystia.sln
    ```

9. The build produces `BepInEx/plugins/MetaMystia-v<version>.dll` and copies `MetaMystia.Preloader.dll` into `BepInEx/patchers/MetaMystia`.

The main project targets .NET 6.0 and currently uses C# 14 syntax, so install the .NET 10 SDK in your development environment. The source generator project targets .NET Standard 2.0. Running test projects such as `src/MetaMystia.Network.Tests` and `src/MetaMystia.Flow.Tests` also requires the .NET 6 runtime.

## Tools

For efficient mod development and reverse engineering, prepare the following tools in advance.

### Core tools

#### IDA Pro

Used to disassemble and analyze `GameAssembly.dll`, and to do dynamic debugging when necessary. For IL2CPP games, IDA helps inspect the control flow and call relationships of native code.

- Official website: [https://hex-rays.com/ida-pro](https://hex-rays.com/ida-pro)

> [!NOTE]
> IDA Free can handle basic analysis, but its features and plugin support differ from Pro. Choose a legally licensed edition based on the features you need; this document does not provide any way to crack or circumvent licensing.

#### dnSpyEx

Used for static analysis of .NET assemblies. In IL2CPP scenarios it is mainly used to inspect the dummy DLLs generated by Il2CppDumper to understand class structure, field layout, and method signatures. The original `dnSpy/dnSpy` repository is archived, so the maintained dnSpyEx fork is used here.

- GitHub repository: [https://github.com/dnSpyEx/dnSpy](https://github.com/dnSpyEx/dnSpy)

#### Il2CppDumper

Used to analyze the binaries produced by IL2CPP, restore symbol information, and generate helper files for dnSpy and IDA.

- GitHub repository: [https://github.com/Perfare/Il2CppDumper](https://github.com/Perfare/Il2CppDumper)

### Recommended plugins (optional)

#### IDA-Pro-MCP

This plugin lets AI agents access the IDA database through an MCP interface; it can help locate functions, understand control flow, or speed up analysis.

- Installation reference: [https://github.com/mrexodia/ida-pro-mcp?tab=readme-ov-file#installation](https://github.com/mrexodia/ida-pro-mcp?tab=readme-ov-file#installation)

#### dnSpy.Cpp2IL

A dnSpy plugin that integrates Cpp2IL analysis results into the dnSpy view, providing more information when reading decompiled IL2CPP code. Before installing, check the plugin repository's instructions to confirm compatibility with your dnSpy version.

- Installation reference: [https://github.com/BadRyuner/dnspy.Cpp2IL?tab=readme-ov-file#how-to-install](https://github.com/BadRyuner/dnspy.Cpp2IL?tab=readme-ov-file#how-to-install)

## Preparing the reverse-engineering environment

This section explains how to prepare the IL2CPP analysis environment with the tools above. Once done, you can browse the restored type structure in dnSpy and do symbol-assisted disassembly analysis in IDA.

### Restoring symbols with Il2CppDumper

1. Run `Il2CppDumper.exe`.

2. Load the following files in order as prompted:
    - `GameAssembly.dll` in the game directory
    - `Touhou Mystia Izakaya_Data/il2cpp_data/Metadata/global-metadata.dat`

3. Wait for the automatic analysis to finish. It produces several output folders; the following steps mainly use:
    - `DummyDll/`

### Importing into dnSpy

1. Import the `DummyDll/Assembly-CSharp.dll` generated by Il2CppDumper into dnSpy.

2. Through this file you can inspect class definitions, field names, and method signatures in the game logic fairly directly, and locate their virtual addresses in the DLL.

### Importing into IDA Pro

1. Open `GameAssembly.dll` with IDA Pro and wait for the initial auto-analysis (the first load may take a while).

2. In IDA, click `File -> Script file` and run the `ida_with_struct.py` script generated by Il2CppDumper. Some versions name the Python 3 script `ida_with_struct_py3.py`; use whatever the actual output contains.

3. Follow the script prompts to select the generated `script.json` and `il2cpp.h` files, then wait patiently for the symbols and structures to finish importing.

    ![Steps to run the script in IDA](./getting_started.assets/image-20251231124728238.png)

4. When the import finishes, close IDA and **save the database**. In the save dialog, it is recommended to check the `Collect` option to keep the full analysis information.

    ![IDA save dialog](./getting_started.assets/image-20251231125239242.png)

5. Back up the generated `GameAssembly.dll.i64` database file separately.

> [!TIP]
> During dynamic debugging, **ASLR** makes the module's runtime base address (e.g. `0x7FFF25021000`) different from the address in static analysis (e.g. `0x180001000`), which easily causes confusion. Keeping a copy of the original static database avoids the Rebase affecting static analysis.

### Helper skill

AI agents can help search call relationships and organize audit records, but game behavior should still be cross-verified with the reversed code, the interop assemblies, and actual runtime results. When you need to restore IL2CPP source with IDA Pro MCP, see [il2cpp-to-csharp-skill](https://github.com/MetaMikuAI/il2cpp-to-csharp-skill).

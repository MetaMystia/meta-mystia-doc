# ID署名検証の仕組み

ResourceExはIDでキャラクター、食材、料理、レシピ、飲み物などのリソースを区別します。2つのリソースパックが同じIDを再利用すると、ゲームが誤った内容を読み込むことがあります。管理ID範囲と署名の仕組みは、こうした衝突を減らすためのものです。

署名は、ある`label`が一定のID範囲を使うことを許可された証であり、MetaMystiaがそのリソースパックの内容を承認・支持・推奨するものではありません。

## IDの範囲

| 範囲                         | ルール                                                                 |
| ---------------------------- | ---------------------------------------------------------------------- |
| `-2147483648`から`8999`      | ゲーム予約領域。ResourceExでは使用禁止                                 |
| `9000`から`1073741823`       | 管理領域。有効な範囲の宣言が必要で、検証が有効な場合は有効な署名も必要 |
| `1073741824`から`2147483647` | 自由領域。署名は不要だが、衝突リスクは作成者が負担                     |

リソースパックが管理IDを使う場合、`packInfo.idRangeStart`と`packInfo.idRangeEnd`で範囲を宣言する必要があります。開始値は終了値より大きくできず、すべての管理IDが宣言範囲内に収まっている必要があります。自由領域のIDだけを使うパックはこの2つのフィールドは不要です。

## ID範囲の申請

次のいずれかの窓口から、リソースパックの`label`と使用したい連続ID範囲を提出できます：

- QQグループ：[1034953242](https://qm.qq.com/q/s0Qp3QPtOC)
- メール：[`MetaMiku@hotmail.com`](mailto:MetaMiku@hotmail.com)
- GitHub Issue：[MetaMystia Issues](https://github.com/MetaMystia/MetaMystia/issues)

通常は1000個単位で範囲が割り当てられます：

$$
[1000n, 1000n+999],\quad n\in\mathbb{Z}
$$

より広い範囲が必要な場合は、用途を説明して連続した区間を申請してください。ID範囲の拡張や`label`の変更を行わない限り、署名済みのパックはバージョン更新のたびに再申請する必要はありません。

申請前に[MetaMystia-ResourceEx ID割り当て表](https://docs.qq.com/sheet/DV2NvRFVKYmJBWGVK)を確認し、割り当て済みの範囲を避けてください。サンプルパック`ResourceExample`は現在`9000`から`12999`を使用しており、サードパーティのリソースパックは再利用できません。

## 署名が対象とする内容

署名は次のUTF-8テキストに結び付きます：

```text
label:idRangeStart-idRangeEnd
```

ローダーは組み込みの公開鍵を使い、RSA-2048、SHA-256、PKCS#1 v1.5で検証します。`label`やID範囲を変更すると、元の署名は無効になります。

オンラインエディターで`label`とID範囲を入力したら、「署名」機能で承認済みの署名文字列を貼り付けて保存します。

## 一時的な開発と自由領域

署名を待つ間は、`BepInEx/config/MetaMystia.cfg`の`General`セクションで`SignatureCheck`を`false`にできます。これはローカルの開発とデバッグにのみ適しています。

署名検証をオフにしても、次のルールは引き続き適用されます：

- `8999`以下のゲーム予約IDの使用は禁止；
- 管理IDはリソースパックが宣言した範囲内でなければならない；
- 管理IDを使う場合、開始と終了の範囲そのものが有効でなければならない。

署名を申請したくない場合は、`1073741824`以上の自由領域のIDを使えます。自由領域はリソースパック同士の衝突を解決するものではなく、公開者が自主的に調整する必要があります。

# ID 서명 검증 메커니즘

ResourceEx는 ID로 캐릭터, 재료, 요리, 레시피, 음료 등의 리소스를 구분합니다. 두 리소스 팩이 같은 ID를 재사용하면 게임이 잘못된 내용을 로드할 수 있습니다. 관리 ID 구간과 서명 메커니즘은 이런 충돌을 줄이기 위한 것입니다.

서명은 특정 `label`이 일정 ID 구간을 사용하도록 허가받았다는 뜻이며, MetaMystia가 해당 리소스 팩의 내용을 인정, 지원, 추천한다는 의미는 아닙니다.

## ID 범위

| 범위                          | 규칙                                                                             |
| ----------------------------- | -------------------------------------------------------------------------------- |
| `-2147483648`부터 `8999`      | 게임 예약 영역으로 ResourceEx에서 사용 금지                                      |
| `9000`부터 `1073741823`       | 관리 영역으로 유효한 범위 선언이 필요하며, 검증이 켜져 있으면 유효한 서명도 필요 |
| `1073741824`부터 `2147483647` | 자유 영역으로 서명은 필요 없지만 충돌 위험은 창작자가 부담                       |

리소스 팩이 관리 ID를 사용하면 `packInfo.idRangeStart`와 `packInfo.idRangeEnd`에 범위를 선언해야 합니다. 시작 값은 종료 값보다 클 수 없고, 모든 관리 ID가 선언된 범위 안에 있어야 합니다. 자유 영역 ID만 사용하는 팩은 이 두 필드가 필요하지 않습니다.

## ID 구간 신청

다음 경로 중 하나로 리소스 팩 `label`과 사용하려는 연속 ID 구간을 제출할 수 있습니다:

- QQ 그룹: [1034953242](https://qm.qq.com/q/s0Qp3QPtOC)
- 이메일: [`MetaMiku@hotmail.com`](mailto:MetaMiku@hotmail.com)
- GitHub Issue: [MetaMystia Issues](https://github.com/MetaMystia/MetaMystia/issues)

보통 1000개 단위로 구간이 배정됩니다:

$$
[1000n, 1000n+999],\quad n\in\mathbb{Z}
$$

더 넓은 범위가 필요하면 용도를 설명하고 연속 구간을 신청하세요. ID 구간을 확장하거나 `label`을 바꾸지 않는 한, 서명된 팩은 버전 업데이트 때 다시 신청할 필요가 없습니다.

신청 전에 [MetaMystia-ResourceEx ID 배정표](https://docs.qq.com/sheet/DV2NvRFVKYmJBWGVK)를 확인해 이미 배정된 범위를 피하세요. 예시 팩 `ResourceExample`은 현재 `9000`부터 `12999`까지 사용하며, 서드파티 리소스 팩은 재사용할 수 없습니다.

## 서명이 대상으로 하는 내용

서명은 다음 UTF-8 텍스트에 결합됩니다:

```text
label:idRangeStart-idRangeEnd
```

로더는 내장 공개 키로 RSA-2048, SHA-256, PKCS#1 v1.5 검증을 수행합니다. `label`이나 ID 구간을 수정하면 기존 서명은 무효가 됩니다.

온라인 에디터에서 `label`과 ID 범위를 입력한 뒤 '서명' 기능으로 승인된 서명 문자열을 붙여 넣고 저장하세요.

## 임시 개발과 자유 영역

서명을 기다리는 동안 `BepInEx/config/MetaMystia.cfg`의 `General` 섹션에서 `SignatureCheck`를 `false`로 설정할 수 있습니다. 이는 로컬 개발과 디버깅에만 적합합니다.

서명 검증을 꺼도 다음 규칙은 그대로 적용됩니다:

- `8999` 이하의 게임 예약 ID 사용 금지;
- 관리 ID는 리소스 팩이 선언한 범위 안에 있어야 함;
- 관리 ID를 사용할 때 시작과 종료 범위 자체가 유효해야 함.

서명을 신청하고 싶지 않다면 `1073741824` 이상의 자유 영역 ID를 사용할 수 있습니다. 자유 영역은 서로 다른 리소스 팩 간의 충돌을 해결해 주지 않으며, 배포자가 직접 조율해야 합니다.
